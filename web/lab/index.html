ARGOS Lab · UI refresh · 2026-11-01 Theme

The refreshed ARGOS interface, as working prototypes

Four labs built by the design team on synthetic data: the Observe workspace in its four task modes and the Watch view, the live charts, the control system, and the stack research behind them. They import the app's tokens, icons and components read-only; nothing here is wired to the telescope, and the lab is not the app.

Every page reads ?theme=observatory|charcoal|night-red and ?motion=reduced. The links below carry the theme chosen above. Synthetic nights: RR Lyr (a replay modelled on the totals of the owner's 2026-09-25 run, not his data) and SW And (a synthetic ephemeris).

  • PROPOSAL.md: the synthesis for the owner Direction in seven principles, every proposal adopted, adapted or rejected with its reason, BRAND amendments, tokens, promotion by wave, WebKit risks, decisions.
  • Functional spaces of an ARGOS night UX research: 13 tasks from preparation to the morning after, reading distance, findings from three real nights.
  • What our stack can do Svelte 5, uPlot, Canvas, WebGL2 and CSS, measured in Chromium 156 and a macOS 26.5 WKWebView.

Live charts

charts.html

uPlot charts on one simulated clock: linked facets, zoom that new frames never move, UTC / JD / BJD, the age of the last frame on the time axis, rules drawn where they fire.

  • Light curveTarget, check (trailing ±1σ band) and comparison ensemble on one linked axis; fit, follow, zoom kept.
  • Plot wallReview: one star per cell, session health strip, linked cursor and zoom, selected time across cells.
  • V-curveAutofocus point by point; weighted hyperbola fit with ±1σ; vertex provisional until decided.
  • ConditionsHFD, stars, sky, airmass to "now"; the gap is the last frame's age, hatched when overdue.
  • VisibilityTwilight as luminance steps, minimum-altitude handle, transit, Moon, planned run and frames taken.
  • HistogramKeyboard B / M / W handles, clipped-to-black and -white fractions, the exact display ramp.
  • Mini chartsSparklines and meters for chips, rail rows and glance tiles; normal, attention, stale, no data.
  • In contextCharts at true size in an Observe › Run mock (superseded by the workspace's Run; kept for scale).

Controls

controls.html

One control button in every state, the time ring, value fields that send one value per commit, the focuser gauge, the jog pad with a visible dead-man, hold-to-confirm.

  • ButtonsRest to error, busy, progress ring and hold ring; unavailable controls say why when pressed.
  • ToolbarsBuilt from data, priority overflow that counts what it holds, split buttons, key hints while ⌘ is held.
  • ValuesScrub fields with a visible commit model, steppers that repeat, sliders with ticks, detents and fine drag.
  • FocuserTwo-scale travel gauge, queued taps, Go to that never moves on blur, Halt always available.
  • Mount jogAlt / Az keys on the alt-az Seestar, two axes at once, renewal age, server stop after 1 s.
  • Confirm and progressHold 0.7 s for Park and Pause-and-slew; Enter opens the inline confirmation; progress inside buttons.
  • Status and keysChips double-coded, attention levels by mark and word (never the check star's triangle), key caps.

Stack research

research.html

The techniques underneath, measured in both engines: big data outside Svelte's proxy, uPlot plugins, a 2 Mpx frame per second, motion rules, popovers, a 10 000-row table, a support matrix.

  • Light curveShape-coded markers and error bars in one Path2D, stability band, draggable HFD threshold, 50 000 points.
  • Frame 1 fpsWorker statistics, WebGL2 R16UI upload, perceptual (OKLCH) Fire and Ice palettes.
  • MotionSpring, Tween and flip for orientation only; values jump; reduced motion is instant.
  • SpaceResizable rail and drawer, container queries, subgrid forms, :has() validation.
  • PopoverPopover API with anchor positioning, and the script fallback WKWebView needs on an old SDK.
  • Table10 000 frames in 41 DOM rows, keyboard grid, filter painted with the Custom Highlight API.
  • SupportFeature detection and micro-benchmarks in this engine, beside the recorded Chromium and WebKit runs.

Run it

cd web
npx vite --port 5205 --strictPort        # then open http://localhost:5205/lab/index.html

# screenshots (system Chrome through puppeteer-core), one script per lab
node src/lab/workspace/capture.mjs --base http://localhost:5205 --out /tmp/ws
node src/lab/charts/capture.mjs    --base http://localhost:5205/lab/charts.html --out /tmp/ch
node src/lab/controls/capture.mjs  --base http://localhost:5205/lab/controls.html --out /tmp/ct
node lab/research/demos/capture.mjs --base http://localhost:5205/lab/research.html --out /tmp/rs

# Night Red pixel audit (both rules) and brass count, no dependency
node lab/synthesis/audit-png.mjs --brass /tmp/ws/*.png

The labs never write the app's argos.* storage keys and request nothing outside the machine.
