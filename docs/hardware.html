Hardware

Which numbers we’ll stand behind

0.4.1 opens Argos to the Seestar family. That raises a question worth answering directly rather than in a footnote: the software will run on more than one telescope, but it will only vouch for one of them — and it says which, in the interface, in the logs, and here.

Telescope profiles

Every number below is either measured on the instrument or taken from the manufacturer’s published specification. Nothing is interpolated to fill a gap.

Model Aperture Focal f/ Sensor Array Scale Field Status
Seestar S30 Pro 30 mm 160 mm 5.3 IMX585 3840×2160 3.74″/px 3.99°×2.24° Reference
Seestar S30 30 mm 150 mm 5.0 IMX662 1920×1080 3.99″/px 2.13°×1.20° Unvalidated
Seestar S50 50 mm 250 mm 5.0 IMX462 1920×1080 2.39″/px 1.28°×0.72° Unvalidated

Plate scales are per raw sensor pixel. Measurements happen on the green half-resolution plane, so the effective sampling for photometry and astrometry is twice these figures — 7.48″ per green pixel on the S30 Pro. Resolution is read from the driver at connect; the array sizes above are only the fallback. And the scales the published optics imply match ZWO’s own field-of-view figures, which is a genuine cross-check on the S30 and S50 optics even though their sensors remain unconfirmed.

What “unvalidated” actually means

Not a disclaimer. A list of three specific unknowns, each of which would corrupt a magnitude in a specific way.

Unconfirmed on the S30 and S50
  • Bayer pattern assumed GRBG. This is the one that matters most, because a wrong CFA layout does not fail loudly — it quietly measures the wrong photosites and poisons every magnitude derived from them.
  • Seestar gain scale and EGAIN curve. Converting ADU to electrons requires a photon-transfer calibration on the actual instrument. Without it the CCD-equation error budget is scaled by an unknown factor.
  • ADC depth and saturation thresholds are inherited from the S30 Pro, which means the linearity limit that guards against saturated measurements has not been checked on these bodies.

The consequence is enforced in code rather than left to the observer’s memory. Selecting an unvalidated profile is allowed — framing, sequencing, plate solving and FITS writing all work — but the software surfaces the caveats in the interface and logs each one on activation. Where a photometric quantity would have to be invented, it is left out of the header instead: when the sensor is unknown, Argos prefers the driver’s own electron gain, and failing that writes no EGAIN at all rather than a plausible-looking number. An empty header field is recoverable. A confidently wrong one is not.

At connect, the camera name and the driver’s reported resolution are compared against the active profile. On mismatch Argos warns in the status bar and logs it — it never switches profile silently in the middle of a session.

The S50 Pro is deliberately absent

Its optics are published — 50 mm, 260 mm, f/5.2 — but its sensor is described only as “1/1.2-inch 4K”. Without a confirmed pixel pitch there is no plate scale, and the plate scale is the one number the entire astrometry path depends on.

A profile that cannot be filled honestly is worse than a missing one, so it ships when the specification does.

Beyond the Seestar

The device layer is generic. The Seestar is simply the instrument it was built and validated against.

ASCOM Alpacathe transport
Argos talks to the telescope over Wi-Fi through the Alpaca protocol, and the same code path serves any Alpaca-compatible camera, focuser or filter wheel. Nothing in that layer is Seestar-specific.
Simulatorno telescope needed
The ASCOM Alpaca simulator (OmniSim) runs in Docker and exercises the entire application — connection, sequencing, capture and the photometry workflow — without any hardware. It is how most of Argos is developed and tested.
Stellariumoptional
The telescope protocol is supported for pointing. It carries ICRS coordinates only, so Argos never rewrites the FITS OBJECT value from a GoTo — the observer chooses the intended target.
ASTAPexternal, required for solving
Plate solving is delegated to ASTAP and its star database. Argos never bundles either: you install them, and point Settings → Astrometry at the executable and the database folder. Everything else works without them; only the WCS-dependent features do not.

Requirements

Argos runs on your laptop, beside the telescope, and sends nothing anywhere.

Platform Delivery Status Notes
macOS .dmg / from source Developed on The reference platform. The 0.4.1 disk image is unsigned — Gatekeeper will need an explicit override.
Debian / Ubuntu .deb (x86_64) Technical preview Builds and smoke-tests in CI on every tag. It has never been through a real observing night on Linux.
Windows — Not yet No package and no validation. Running from source is untested rather than known-broken.
Also needed
  • ASTAP and a star database for plate solving — installed separately, detected at startup, configurable by hand.
  • Disk space for raw subs. Argos keeps every frame; that is the point.
  • Internet, occasionally. Catalogue lookups (AAVSO, CDS, NASA) are cached locally, so a field session works offline once you have resolved your targets at home.
  • Siril for the reduction half of the workflow, if you want a publishable curve.

Argos sends no telemetry and never uploads session data. Catalogue queries happen only when you ask for one.

Get it

0.4.1 is an alpha for technically confident observers who keep their raw FITS and check the results independently. Installers are attached to the GitHub release; the source path works everywhere the dependencies do.

from source 
brew install uv
git clone https://github.com/jperret21/argos.git
cd argos
uv sync --extra dev
uv run python main.py
