Review / ARGOS 0.4.1

Review a session.

Open a finished session, trace a curve point back to its FITS, export, and file a report without uploading anything.

After the night

Review reads session.json and the saved FITS headers, so a completed session opens with no telescope connected, on any computer.

It is read-only: it never modifies a raw frame, and it does not replace calibration.

01

Open the right folder

  1. Select Review in the sidebar.
  2. Press Open session… and choose the folder containing session.json — <timestamp>_<OBJECT>/, not the lights/ subfolder inside it.
  3. Missing or malformed frames are reported as warnings and the rest of the night still loads.

If you copied a session off the telescope computer, copy the whole folder. It is the only link between the frames, the observing context, the selected stars and the preview measurements.

03

Inspect the frame behind a curve point

Hover a curve point to read its recorded values. Select it and press Open source frame to open the nearest light frame in the FITS viewer; the Frames dock opens the same file by double-click. In the viewer you can read the header, measure, and plate-solve the frame. Nothing is written back.

The loopCurve anomaly → source frame → header → keep the frame. Never delete frames because an uncalibrated preview looks odd.

04

Export and hand off

Export measurements… writes target, check and comparisons to CSV, which Open curve CSV… reopens here. Export target (AAVSO)… writes the science target only: comparison curves are diagnostics and must never be submitted as observations. Open FITS… inspects any single frame.

Copy the whole session folder before you run Siril.

05

Report a problem

ARGOS has no telemetry, analytics or automatic crash upload; logs and crash reports stay on the computer. Choose More → Create local support bundle… and pick where the ZIP goes.

The support bundle is local and explicit by design
Included when selectedExcluded or redacted
Redacted rotating ARGOS logs, manifest.json with application and platform information, README.txt, and — only if you select a session folder — bounded .json, .csv and .jsonl metadata.Raw FITS and other binary data; observer identity; site coordinates; IP addresses, rewritten <redacted-ip>; home paths, rewritten ~.

Open the ZIP and read it before you send it. ARGOS never sends it.

What makes a useful report

  • ARGOS version, operating system and Seestar model.
  • What you expected, what happened, and the exact error text.
  • The time of the event and the action before it.
  • The support bundle, after you have looked inside it.
  • A raw FITS only if someone asks for it.
